# Установка и настройки

## Требования

- Установленный клиент ЛОЦМАН:PLM (даёт `DataProvider.dll` в
  `Program Files (x86)\Common Files\ASCON Shared\Loodsman\` и запись
  сервера приложений в реестре `HKCU\Software\ASCON\Loodsman`).
- Python 3 с стандартной библиотекой (сторонних пакетов нет).
- Работать скрипты могут из любого 32-битного COM-хоста; набор вызывает
  `cscript` из `SysWOW64` (на 64-битной Windows) — 64-битный Python сам
  является лишь оркестратором, COM-слой живёт в 32-битном cscript.

## Клон и хуки

Клонировать в `<папка скиллов>/loodsman-skill` рядом с skill-skill;
`git config core.hooksPath ../skill-skill/hooks`; автор — как у клона
skill-skill. Проверка перед коммитом:
`python tools/check_docs.py --project "<папка проекта>"`.

## Локальные настройки (не под git)

`local/loodsman.ini` — **ANSI (cp1251)**, читается VBS:

```
db=<имя базы, как в клиенте>
linkComposition=<имя связи состава>
linkDocuments=<имя связи документов>
```

`local/config.json` — UTF-8, читается Python (пути и значения конкретной
установки): `tsv_dir`, `project_dir`, `db`, `tree_folder` (узел дерева
проектов для гиперссылок), `root_id`, `root_title`, `include`
(разрешённые расширения через запятую).

Шаблоны обоих файлов лежат рядом (`*.шаблон`). В репозиторий пути,
имена баз и серверов не попадают — стоп-лист `local/stoplist.txt`
(skill-skill 40-02) и проверка `--project`.

## Имена связей в базе

Узнать точные имена связей состава и документов своей базы:
`GetLinkList(idVersion любого объекта)` → поля `_NAME/_INVERSENAME`
(состав обычно «Состоит из …» с многоточием, документы — «Документы»).
