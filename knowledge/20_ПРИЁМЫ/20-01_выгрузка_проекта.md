# Цикл выгрузки проекта

Настройки — в `local/loodsman.ini` (db, имена связей) и `local/config.json`
(пути, root_id, фильтр расширений). Форматы — в 40-01.

```bash
# 1. Сканировать дерево: объекты+файлы в TSV (метаданные и CRC, без скачивания)
python scripts/check_versions.py                # scan + сравнение с прошлым разом
cscript //Nologo scripts/loodsman_export.vbs scan <rootId> <tsvDir>

# 2. Скачивать (фильтр: include важнее exclude, расширения через запятую)
cscript //Nologo scripts/loodsman_export.vbs fetch <tsvDir> <outDir> "" "pdf,docx,spw"

# 3. Индекс: index.md (дерево + ссылки ask:Loodsman.URL), versions.json, *.url
python scripts/build_index.py

# 4. Проверка версий + догрузка изменений (по CRC, без перекачки неизменного)
python scripts/check_versions.py --fetch
```

## Как это работает

- `scan` рекурсивно обходит состав (`GetTree` по связи состава, один уровень
  за вызов) и документы каждого объекта (связь документов); для каждого
  документа — `GetInfoAboutVersion` режим 7 (файлы: `_NAME, _SIZE, _CRC,
  _MODIFIED`). Дерево бывает цикличным — в `build_index.py` обход с защиты.
- `fetch` для каждого файла вызывает `GetFileById(idДокумента, имя, "")` →
  путь на файловом сервере → копирование SMB. Пропускает уже скачанное по
  размеру; повторный запуск безопасен. Статус в `files_done.tsv` — по
  результату попытки: fetched/filtered/error (30-06).
- `_CRC` из API — стандартный CRC32 файла: контроль целостности после
  скачивания и детект изменений без перекачки (совпадение проверено
  на сотнях файлов).
- `check_versions.py --fetch` сравнивает свежий `files.tsv` с
  `versions.json`, удаляет локально изменившиеся и скачивает только их.
- Гиперссылка на объект:
  `ask:Loodsman.URL?Action=Navigate,params=base64(cp1251("0|База|узелДерева|idВерсии"))`.
  Вставляется в адресную строку проводника — клиент откроется и выделит
  объект. `build_index.py` пишет такие ссылки в `index.md` и `.url`-файлы
  в папках документов.

## Ограничения

- Файлы без тела в базе (автогенерируемые ПЭ3/отчёты) не скачиваются
  (30-03) — в выгрузке их помечать «нет в базе», не считать ошибкой.
- Лицензия Лоцман занята на время scan/fetch — длинные выгрузки лучше
  запускать вне пикового времени.
- scan на 900 объектов — порядка минут; в этот время лицензия занята.
